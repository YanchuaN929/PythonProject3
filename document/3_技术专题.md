## 一、Registry 模块架构

### 1.1 系统概述

Registry 是一个任务状态追踪系统，用于：

1. **记录任务首次出现的时间**
2. **追踪任务状态变化**（待处理 → 待审查 → 已确认）
3. **保持状态一致性**：即使 Excel 文件变化，任务状态也不丢失

### 1.2 核心数据结构

**任务标识（Task ID）**：

```
task_id = SHA1(f"{file_type}:{project_id}:{interface_id}:{source_file}:{row_index}")
```

- 唯一标识一条任务记录
- row_index 变化会产生新的 task_id

**业务标识（Business ID）**：

```
business_id = f"{file_type}|{project_id}|{interface_id}"
```

- 唯一标识一个接口（不含行号）
- 用于状态继承：即使行号变化，同一接口的状态可以继承

### 1.3 数据库表结构（tasks 表核心字段）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | TEXT | 任务唯一 ID (SHA1) |
| business_id | TEXT | 业务 ID (用于跨文件继承) |
| file_type | INTEGER | 文件类型(1-7) |
| project_id | TEXT | 项目号 |
| interface_id | TEXT | 接口号 |
| status | TEXT | 状态(open/completed/confirmed/archived) |
| display_status | TEXT | 显示状态(待完成/待审查/已审查等) |
| responsible_person | TEXT | 责任人 |
| assigned_by | TEXT | 指派人 |
| assigned_at | TEXT | 指派时间 |
| completed_at | TEXT | 完成时间 |
| completed_by | TEXT | 完成人 |
| confirmed_at | TEXT | 确认时间 |
| confirmed_by | TEXT | 确认人 |
| ignored | INTEGER | 是否忽略(0/1) |
| interface_time | TEXT | 预期时间 |
| first_seen_at | TEXT | 首次发现时间 |
| last_seen_at | TEXT | 最后出现时间 |
| archived_at | TEXT | 归档时间 |

### 1.5 状态继承与重置

**继承条件**（同一 business_id 的任务）：

- interface_time 未变化 → 继承 display_status、status、完成/确认信息
- 已有指派信息 → 继承 assigned_by、assigned_at、responsible_person

**重置条件**：

- interface_time 变化 → 重置状态为 open/待完成
- 完成列从有值变为空 → 归档旧记录，创建新记录

### 1.6 处理流程中的 Registry 交互

```
Excel 筛选（core/main.py）
        ↓
┌───────────────────────────────────────┐
│ Step 1: 4步筛选逻辑                   │
│ 输出: final_rows (如 300 行)          │
└───────────────────────────────────────┘
        ↓
┌───────────────────────────────────────┐
│ Step 2: Registry 查询加回             │
│ 查询待审查/待指派人审查的任务         │
│ 验证是否通过 process1 筛选条件        │
│ 加回到 final_rows 中                  │
└───────────────────────────────────────┘
        ↓
┌───────────────────────────────────────┐
│ Step 3: 角色筛选（base.py）           │
│ 输出: 用户实际看到的数据 (如 150 行)  │
└───────────────────────────────────────┘
        ↓
┌───────────────────────────────────────┐
│ Step 4: Registry 写入（hooks.py）     │
│ 写入的是角色筛选前的数据              │
│ 增量更新：仅文件变更时触发            │
│ 管理员角色才执行 scan_finalize        │
└───────────────────────────────────────┘
```

**关键点**：

- Registry 写入的是 Excel 筛选后、角色筛选前的数据
- Registry 查询加回时验证 process1 条件，避免"幻觉"数据
- 增量写入策略：文件未变化时跳过 Registry 写入

## 二、数据库并发优化方案

### 2.1 已实现的优化措施

| 功能 | 实现位置 | 说明 |
|------|----------|------|
| ✅ 并行文件读取 | `base.py` | `ThreadPoolExecutor` 并发读取 Excel |
| ✅ 文件缓存机制 | `services/file_manager.py` | 基于文件哈希的 pkl 缓存 |
| ✅ 数据库索引 | `registry/db.py` | 多个任务表索引 + 事件表索引 |
| ✅ WAL 模式自动切换 | `registry/db.py` | 本地用 WAL，网络盘用 DELETE |
| ✅ 重试机制 | `registry/hooks.py` | 锁定时指数退避重试 |
| ✅ 本地只读缓存 | `registry/local_cache.py` | 读操作零网络 IO |
| ✅ 直接事务写入 | `registry/hooks.py` | 网络锁冲突重试，写后缓存失效 |
| ✅ 读写分离 | `registry/db.py` | 读用本地缓存，写用网络盘 |
| ✅ 增量 Registry 更新 | `base.py` | 文件未变化时跳过写入 |
| ✅ UI 渲染去重 | `base.py` | 处理完成仅渲染当前 tab |

### 2.2 网络盘 WAL 模式问题（已修复）

**问题**：SQLite WAL 模式在网络文件系统（SMB/CIFS）上导致独占锁，第二个用户无法访问数据库。

**解决方案**：

- 自动检测网络路径（UNC 路径 `\\server\share` 或映射驱动器）
- 网络路径自动禁用 WAL 模式，改用 DELETE 模式
- 清理旧的 WAL 辅助文件（`.db-shm`、`.db-wal`）
- 增加超时时间（连接 60 秒，繁忙 30 秒）

### 2.3 读写分离架构

```
     用户 ──── 【读取】从本地缓存读 ──── 本地 registry_local.db
                                              ↑
                                              │ 定期同步(5分钟)
                                              ↓
     用户 ──── 【写入】直接事务写入 ──→ 网络盘 registry.db
```

- **读操作**：全部从本地缓存读取，无网络 IO，瞬间响应
- **写操作**：Excel 写回由 write_tasks 排队；Registry 在 Excel 成功后直接事务写入网络盘
- **同步**：写入后自动使本地缓存失效，下次读取时重新同步

### 2.4 维护模式

- 管理员可创建维护标志文件 `<data_folder>/.registry/maintenance.lock`
- 其他客户端检测到维护模式后：关闭连接、弹窗提示，退出程序
- 用于数据库维护、备份等场景

## 三、自动更新机制

### 3.1 架构概述

系统由三个核心组件构成：

1. **主程序** - 集成 UpdateManager，负责版本检查和优雅退出
2. **更新管理器**（`update/manager.py`）- 版本比较和更新触发
3. **独立更新器**（`update/updater_cli.py` → `update.exe`）- 独立进程执行文件复制

### 3.2 更新流程

```
主程序启动/操作前
        ↓
┌─────────────────┐      ┌─────────────────┐
│  读取本地版本   │ ←──→ │  读取远程版本   │
│  version.json   │      │  EXE/version.json│
└────────┬────────┘      └─────────────────┘
         ↓
    版本比较 (YYYY.MM.DD.N)
         ↓
┌─────────────────┐      ┌─────────────────┐
│  版本一致       │      │  版本落后       │
│  继续执行       │      │  触发更新       │
└─────────────────┘      └────────┬────────┘
                                  ↓
                         ┌─────────────────┐
                         │  启动 update.exe│
                         │  主程序优雅退出 │
                         │  等待主进程结束 │
                         │  复制新版本文件 │
                         │  重启主程序     │
                         │  (带 --resume)  │
                         └─────────────────┘
```

### 3.3 版本号格式

格式：`YYYY.MM.DD.N`（如 `2026.02.06.1`）

比较规则：四段整数逐位比较

### 3.4 部署目录结构

**服务器端**：

```
ServerRoot/EXE/
├── version.json        # 最新版本号
├── 接口筛选.exe
├── update.exe
└── _internal/          # PyInstaller 依赖
```

**客户端**：

```
ClientRoot/
├── version.json        # 当前版本
├── 接口筛选.exe
├── update.exe
└── _internal/
```

### 3.5 技术细节

- **文件锁处理**：update.exe 循环检测主程序进程是否消失，并尝试写模式打开文件进行锁检测
- **原子更新**：先复制到临时目录，校验无误后再覆盖
- **跳过策略**：跳过 update.exe 自身和被占用的 DLL 文件
- **状态恢复**：更新后通过 `--resume` 参数恢复之前的操作
- **日志**：`update_log.txt` 记录详细更新过程

## 四、写入任务队列系统

### 4.1 设计原则

- 所有前台操作立即返回，由后台异步写入
- UI 通过 PendingCache 即时反映结果
- 写队列防止公共盘 Registry 长时间占用
- 支持重启恢复（持久化缓存）

### 4.2 架构

```
用户操作(指派/回文)
        ↓
┌─────────────────────┐
│ WriteTaskManager     │
│ 提交任务到队列       │
└────────┬────────────┘
         │
    ┌────┴────┐
    ↓         ↓
┌────────┐ ┌────────────┐
│ 持久化 │ │ PendingCache│
│ cache  │ │ UI临时显示  │
└────────┘ └────────────┘
    │
    ↓ (后台线程)
┌─────────────────────┐
│ Executors            │
│ Excel写入 + Registry │
└─────────────────────┘
    │
    ↓
┌─────────────────────┐
│ SharedLog            │
│ 写入日志到registry.db│
│ (跨用户可见)         │
└─────────────────────┘
```

### 4.3 读写冲突防护

- `start_processing` 入口检查写队列是否为空
- 手动模式：有排队任务时弹窗提示
- 自动模式：队列非空时等待，每 20 秒重试

### 4.4 任务面板

- 集成到主界面，显示任务执行状态
- 支持本地任务和共享任务查看
- 失败任务显示错误原因
- 支持按用户筛选

## 五、性能优化策略

### 5.1 缓存复用快路径

当源 Excel 文件未变化时：

1. **跳过重复缓存加载**：刷新阶段已加载的缓存结果在处理阶段直接复用
2. **按文件粒度判定**：仅对变化的文件重新处理，未变化文件跳过
3. **空结果缓存（负缓存）**：对长期无结果的项目也缓存，避免重复读 Excel

### 5.2 Registry 增量更新

- **按文件粒度触发**：仅文件变更或缓存未命中时执行 `on_process_done`
- **scan_finalize 管控**：仅管理员角色开始处理时执行归档
- **日志去噪**：默认汇总输出，`REGISTRY_VERBOSE=1` 开启详细日志

### 5.3 UI 渲染优化

- 处理完成后仅渲染当前活跃 tab，其他 tab 按需渲染
- 程序内部切换 tab 时抑制重复渲染
- 超期过滤和排序每个文件类型仅执行一次

### 5.4 预期性能指标

| 场景 | 优化前 | 优化后 |
|------|--------|--------|
| 首次读取（无缓存） | 5-10秒 | 5-10秒 |
| 二次读取（有缓存） | 2-5秒 | <0.5秒 |
| 写入操作（多人并发） | 可能超时 | <2秒 |
| 显示刷新 | 1-2秒 | <0.3秒 |
